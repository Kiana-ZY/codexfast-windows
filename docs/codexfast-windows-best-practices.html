用快捷方式启动，用只读检查应对更新。

首次配置

只需完成一次。安装依赖、构建生成 CLI、执行静态检查，然后安装桌面快捷方式。

约 3-5 分钟

前置条件

需要

  • Node.js 18.12 或更高版本
  • 当前用户已安装官方 Codex MSIX
  • 项目源码位于固定目录

不要做

  • 不要使用管理员 PowerShell
  • 不要运行 npx codexfast
  • 不要修改 WindowsApps 或 config.toml

安装、构建并检查

在项目目录打开普通 PowerShell。以下命令不会启动或关闭 Codex。

PowerShell · 首次构建 
cd D:\path\to\codexfast-windows

corepack pnpm install --frozen-lockfile
corepack pnpm build
node .\bin\codexfast inspect

通过标准

输出包含 Compatibility inspection completed without launching Codex.

安装桌面快捷方式

快捷方式会隐藏可见 PowerShell 窗口，并用托盘图标维持后台 patch session。

PowerShell · 安装或刷新快捷方式 
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\install-windows-shortcut.ps1

项目移动到其他目录后，从新目录重新执行一次安装命令。

日常启动

先启动 8317 代理，再完全退出旧 Codex，最后通过桌面快捷方式启动新会话。

推荐顺序

01

启动代理

先确认 8317 服务可用。codexfast 不会替你启动或修改 Provider。

02

完全退出原 Codex

退出所有 Codex Desktop 窗口和托盘实例。Codex CLI 进程不属于 MSIX 时不会阻止启动。

03

双击 CodexFast

不需要保留可见终端，但隐藏的托盘、PowerShell 和 Node 后台进程必须继续运行。

04

选择模型和速度

选择 Sol、Terra 或 Luna，并通过 Settings、/fast 或 Intelligence Speed 切换 Fast。

模型与 Fast 预期

模型MaxUltraFast 请求
gpt-5.6-sol支持支持service_tier: "priority"
gpt-5.6-terra支持支持service_tier: "priority"
gpt-5.6-luna支持不应出现service_tier: "priority"

Fast 不等于服务端授权

代理仍需接受对应模型 ID 和 service_tier: "priority"，否则可以忽略或拒绝请求。

需要可见终端时

排查启动输出时，可以不用快捷方式，直接运行下面的命令。该 PowerShell 窗口必须保持打开。

PowerShell · 前台启动 
node .\bin\codexfast launch

Codex 更新后

不要先强行启动。先运行只读 JSON 检查，再根据 classification 决定是否进入手工验证。

更新门禁

第一步：只读检查

inspect --json 不激活、关闭或重启 Codex，也不会读取 Provider 配置。

PowerShell · 更新后审计 
node .\bin\codexfast inspect --json

如何判断结果

结果含义下一步
recorded-static-pass 已记录版本，8 个静态 target 全部通过。 可以进入独立的真实启动验证。
unlisted-signature-compatible 当前用户已注册的新版本尚未记录，但 target pattern 仍兼容。 可以测试，不能直接宣称正式支持。
ok: false 身份、文件快照或 required target 未通过。 停止，不要绕过门禁，先适配新版本。

项目源码更新

项目有新提交时，先更新依赖和生成 CLI，再重新安装快捷方式。

PowerShell · 更新本地项目 
git pull --ff-only
corepack pnpm install --frozen-lockfile
corepack pnpm build
node .\bin\codexfast inspect

powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\install-windows-shortcut.ps1

故障、退出与回滚

先退出 Codex，再处理托盘。无需恢复 app.asar 或数字签名，因为 launcher 不会修改它们。

安全退出

正确退出顺序

01

正常退出 Codex Desktop

不要先结束 launcher，避免当前会话失去 CDP patch 监控。

02

等待 launcher 停止

托盘状态变为 Stopped 后，可以保留托盘等待下次使用，也可以退出托盘。

03

需要回到原版时

从开始菜单正常启动官方 Codex 即可，没有 bundle 备份或签名修复步骤。

日志位置

日志保存在项目目录，达到 5 MB 后轮转。

.\logs\launcher.log
.\logs\launcher.previous.log

仅在自动发现失败时使用覆盖项

覆盖项不应永久写入系统环境。它们不能为未知或未注册的 MSIX 建立信任。

PowerShell · 会话级覆盖示例 
$env:CODEXFAST_APP_BUNDLE = 'C:\Program Files\WindowsApps\OpenAI.Codex_26.707.3748.0_x64__2p2nqsd0c76g0'
$env:CODEXFAST_APP_EXECUTABLE = 'app\ChatGPT.exe'
$env:CODEXFAST_APP_USER_MODEL_ID = 'OpenAI.Codex_2p2nqsd0c76g0!App'

node .\bin\codexfast inspect
PowerShell · 清除覆盖项 
Remove-Item Env:CODEXFAST_APP_BUNDLE -ErrorAction SilentlyContinue
Remove-Item Env:CODEXFAST_APP_EXECUTABLE -ErrorAction SilentlyContinue
Remove-Item Env:CODEXFAST_APP_USER_MODEL_ID -ErrorAction SilentlyContinue

停止条件

出现以下情况时不要继续强行启动

静态检查为 ok: false、required target 缺失/重复、MSIX 身份不一致，或 launcher 报告 runtime patch session 已丢失。

先查看

  • logs\launcher.log
  • node .\bin\codexfast inspect --json
  • 代理是否监听 8317

不要尝试

  • 不要修改或替换 app.asar
  • 不要重签名或重打包 MSIX
  • 不要通过永久覆盖项绕过身份检查
